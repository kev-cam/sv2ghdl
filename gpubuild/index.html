gpubuild

Compile CUDA farm binaries on any machine podman runs — no CUDA install, no GPU, no NVIDIA driver on the build host. Ship only the compiled binary to cloud GPUs, and trust checksums instead of the cloud.

build host needs: podman only run host needs: libcuda.so.1 only cloud sees: binaries, never source

Quick start

# any nvcc command line, run inside the pinned CUDA-devel container
./gpu-cc.sh -O2 -arch=sm_75 -o hello hello.cu
./hello        # on a machine with an NVIDIA driver

The first invocation pulls nvidia/cuda:12.4.1-devel (≈7 GB, once). Compilation is pure CPU: it works in rootless podman on a laptop and in podman on WSL2 identically. The current directory is mounted at /w; paths in your nvcc arguments are relative to it.

Scripts

scriptdoes
gpu-cc.shnvcc in the container. Image pinned by digest (IMG= or IMG_TAG=1 to override), --network=none, cwd mounted at /w. Podman is the supported engine; ENGINE=docker exists if you must.
build_farm.shflow of record for generated simulation models: model.c harness.cu out → device-qualify the model (make_device_model.sh) → fat binary. Targets overridable via GENC=.
make_device_model.shqualifies a generated model’s functions __device__ for nvcc; writes <model>_dev.c.
ship_run.shscp files to any ssh host and run one command in a held-open session: ship_run.sh user@host 'cmd' file...
vast_run.shbinary-only vast.ai session: poll instance to running, attach your ssh key, ship files, run, log. Needs VAST_API_KEY in the environment — the key is used only locally, never copied to the instance.

Fat-binary targets

archhardware
sm_75Turing — T1000, RTX 20-series
sm_86Ampere — RTX 3090, A4000-class cloud boxes
compute_86 PTXJIT at load for newer parts (sm_89 / sm_90+)

cudart links static, so the binary needs only libcuda.so.1 — the driver — on the run host. That covers bare Linux, WSL2 (/usr/lib/wsl/lib/libcuda.so.1), and every stock cloud image we have met.

Security model

The design treats the cloud as untrusted in both directions:

Outbound. Source, RTL, and toolchain never leave your machines. A rented GPU box receives compiled SASS/PTX and test vectors — the same trust level as shipping a product binary. The vast.ai API key stays local: it authenticates API calls from your machine and is never written to the instance.
Inbound. A cloud host owner can read or tamper with anything that runs there, so results are never trusted as such. Certify them: have the workload produce checksums the host could not guess (aggregate result hashes, per-instance checksums) and compare against values computed on hardware you own. A faked run cannot produce the right numbers without doing the work.
Build. The container image is pinned by digest, and the build runs with --network=none — nvcc needs no network, so the build is hermetic and your mounted source cannot leave the container.
PTX caveat. PTX is an intermediate representation and is substantially easier to reverse than SASS. If the model embedded in a binary is IP-sensitive, build SASS-only for third-party hosts (GENC="-gencode arch=compute_86,code=sm_86") and keep PTX-carrying fat binaries for your own hardware.

Field notes

  • A harness’s #define MODEL_C must be #ifndef-guarded or the -DMODEL_C from build_farm.sh loses.
  • Use --threads 4 (build_farm does) — big single-file models compile each -gencode target in parallel.
  • Very large device functions can hold cicc for hours; -Xcicc -O1 cuts that to minutes at a small runtime cost — good for iteration, full opt for measurement.
  • WSL run hosts: processes die when the last wsl.exe session exits — keep the calling ssh session open instead of using nohup.
  • Rootless podman may warn about systemd cgroup sessions and fall back to cgroupfs; the warnings are noise.
  • Cloud instances bill until destroyed: vastai destroy instance <id> when the log is in.
gpubuild is part of the sv2ghdl project’s simulation-acceleration toolchain; the scripts are self-contained and have no dependency on the rest of the repository.
